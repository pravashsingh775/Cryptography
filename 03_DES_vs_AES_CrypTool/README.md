## 📖 Theoretical Background & Mathematical Foundations

### 1. DES (Data Encryption Standard)
- **Standardized:** 1977 (NIST FIPS PUB 46).
- **Structure:** 16-round Feistel network.
- **Block Size:** 64 bits ($8$ bytes).
- **Key Size:** 56 effective bits (plus 8 parity bits = 64-bit key).
- **Key Space:** $2^{56} pprox 7.2 	imes 10^{16}$ keys.
- **Vulnerability:** Completely broken by brute-force search. In 1999, EFF Deep Crack cracked DES in under 22 hours. Triple-DES (3DES) was introduced as a stopgap ($K=112$ or $168$ bits) but suffers from 64-bit block Sweet32 birthday collisions.

### 2. AES (Advanced Encryption Standard - Rijndael)
- **Standardized:** 2001 (NIST FIPS PUB 197).
- **Structure:** Substitution-Permutation Network (SPN) operating on a $4 	imes 4$ byte state matrix.
- **Block Size:** 128 bits ($16$ bytes).
- **Key Sizes:** 128 bits (10 rounds), 192 bits (12 rounds), 256 bits (14 rounds).
- **Key Space:** $2^{128} pprox 3.4 	imes 10^{38}$ keys (Unbreakable by brute force).
- **Round Transformations:**
  1. `SubBytes`: Byte-by-byte non-linear substitution using an inverted Galois Field $GF(2^8)$ S-Box.
  2. `ShiftRows`: Cyclically shifts row bytes to ensure diffusion.
  3. `MixColumns`: Linear matrix multiplication in $GF(2^8)$ to diffuse byte changes across columns.
  4. `AddRoundKey`: Bitwise XOR with round subkey generated by Key Expansion.

### 3. The Avalanche Effect
A cryptographic algorithm possesses high diffusion if flipping a single input bit changes approximately $50\%$ of the output ciphertext bits:

## ❓ Viva-Voce Questions & In-Depth Answers

1. **Q1: Why was DES replaced by AES rather than simply using a larger key with the DES architecture?**
   - **Answer:** DES has a small 64-bit block size that is vulnerable to birthday bound collisions (Sweet32 attack after $2^{32}$ blocks) regardless of key length. Additionally, DES Feistel operations are slow in software, whereas AES was designed from scratch for high efficiency in both hardware and software with a 128-bit block size.

2. **Q2: What is the Avalanche Effect and why is it essential for block cipher security?**
   - **Answer:** The Avalanche Effect states that flipping a single bit in the plaintext or key should cause roughly half (50%) of the ciphertext bits to flip. This ensures complete diffusion, preventing statistical cryptanalysis and linear/differential attacks.

3. **Q3: What are the four core transformations in an AES round?**
   - **Answer:**
     1. `SubBytes`: Non-linear S-Box substitution for **confusion**.
     2. `ShiftRows`: Cyclic byte shifts for inter-column **diffusion**.
     3. `MixColumns`: Matrix multiplication over $GF(2^8)$ for intra-column **diffusion**.
     4. `AddRoundKey`: Key addition via bitwise XOR for **key mixing**.

4. **Q4: Why does the final round of AES omit the MixColumns step?**
   - **Answer:** Omitting `MixColumns` in the final round makes the encryption and decryption structures structurally symmetric and simplifies hardware/software implementation without compromising security.
